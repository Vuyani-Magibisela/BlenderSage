BlenderSage Dev Log

A running record of how the extension is being built: what was done, what was decided and why, and what is still open. Teachers create guided lessons inside Blender; learners follow them with instructions, viewport guidance and automatic checks.

Phase Milestone 1 Target Blender 5.2.2 LTS · Windows Python 3.13.13 (bundled) Updated 2026-10-03

Where things stand

Groundwork is in place: project instructions, a design spec and plan for the development environment, and a working dev container with headless Blender 5.2.2. No extension code exists yet. The next piece of real product work is Milestone 1, Step 0: API spikes that confirm action reports, property-edit signals, viewport screenshots and overlay drawing behave as the plan assumes in Blender 5.2.

Step 0 is a checkpoint. Work stops there and reports findings before any extension skeleton is built.

2026-10-03

Dev container built and verified

  • Image: python:3.13-slim-bookworm plus Blender 5.2.2 for Linux, downloaded from download.blender.org and checked against the official SHA-256 before unpacking to /opt/blender.
  • Blender needed nine system libraries to start headless, found with ldd in one pass: libgl1 libice6 libsm6 libx11-6 libxext6 libxfixes3 libxi6 libxkbcommon0 libxrender1.
  • Inside the container Blender reports 5.2.2 LTS (build d13f752e3b9c) with Python 3.13.13, matching the Windows install.
  • Checked from Windows: a Python error inside Blender returns exit code 1 through docker exec; a mistyped Blender version fails the build with a 404; files round-trip through the shared folder; a stopped container gives a clear error.
  • Container name is fixed as blendersage-dev so Claude Code on Windows can run tests with docker exec.
  • Independent review of the branch: no critical or important issues. Six minor items deferred: add a .gitattributes for line endings, pin package versions, put the Blender checksum in the Dockerfile, and document that shared-folder files show as owned by root.

2026-10-03

Dev container designed and planned

  • Chose a full VS Code Dev Container used by the developer; Claude Code stays on Windows, where it can also reach the Windows Blender 5.2 and the Blender MCP server for UI spikes.
  • The container deliberately does not cover viewport overlays, display scaling or Windows behaviour. Those stay on the Windows install with a manual checklist.
  • Wrote the design spec and a four-task implementation plan.
